## Идея: GPU-векторизация и батчевые вычисления

**Дата обсуждения:** 2025-04-15  
**Статус:** Обсуждено, не реализовано. Требует серьёзной переписи кода.

### Проблема

Текущий подход (последовательный DE + L-BFGS-B для каждой точки `(μ, L)`):
- Слишком медленно для высокого разрешения (128×128 = 16 384 точки)
- Каждая точка требует ~50–100 вызовов `Omega_ren` → часы вычислений
- Нет возможности быстро исследовать параметрическое пространство

### Предлагаемое решение

Полная векторизация: считать `Omega_ren` **одновременно для батча точек** `(μ, L, M, b)` на GPU.

#### Архитектура

```
Сетки: μ[50] × L[50] × M[50] × b[50] = 6 250 000 точек

Разбиваем на батчи по ~10 000 точек (по памяти GPU)

Для каждого батча параллельно:
  1. dU_phys(M, b)          → сумма по (p, phi)
  2. Omega_L(L, b, M)       → сумма по (p1, p2)
  3. Omega_mu_L(μ, L, b, M) → сумма по (n, p) с маской
  4. tree = M²/(2g)
  5. Omega_ren = tree + dU + Omega_L + Omega_mu_L

Для каждой (μ, L) ищем минимум по (M, b) в батче
Уточняем минимум сплайном в окрестности
```

#### Что можно векторизовать

| Функция | Сложность | Оценка ускорения |
|---------|-----------|-----------------|
| `dU_phys(M, b)` | 🟢 Легко. 2D интеграл → сумма по сетке | 50–100× |
| `Omega_L(L, b, M)` | 🟢 Легко. 2D интеграл по p1, p3 | 50–100× |
| `Omega_mu_L(μ, L, b, M)` | 🔴 Сложно. Циклы по n, условные ветвления | 10–30× |

**Главная проблема — `Omega_mu_L`:**

Текущий код использует numba-JIT циклы:
```python
for n in range(Nmax + 1):      # Nmax разный для каждой точки!
    if two_roots:              # условие зависит от M, b
        ...
    integral = ...             # интеграл по p
```

Для GPU нужно заменить на **маскирование + padding**:
- Найти `n_max_global = max(n_max)` для всего батча
- Создать тензор `(batch, n_max_global, N_p)`
- Маской занулить недопустимые `(n, p)` для каждой точки батча
- Суммировать по `n` и `p` векторизованно

#### Оценка памяти (батч = 10 000 точек)

| Тензор | Размер | Память (float64) |
|--------|--------|-----------------|
| `Omega_mu_L` | (10000, 20, 100) | ~160 MB |
| `Omega_L` | (10000, 100, 100) | ~800 MB |
| `dU` | (10000, 100, 100) | ~800 MB |
| **Итого** | | **~1.8 GB** |

Влезает в GPU с 8+ GB памяти.

#### Оценка скорости

**Вся сетка 50×50×50×50 = 6 250 000 точек:**
- Батчей: 625 (по 10 000 точек)
- Время одного батча на GPU: ~1–3 сек
- **Итого: ~10–30 минут**

Сравнение с текущим подходом:
- Последовательный DE: ~6×10⁸ вызовов × 0.01 сек = **~72 дня**
- Параллельно на 4 CPU: **~18 дней**
- GPU батчи: **~10–30 минут**

**Ускорение: ~1000×**

## Идея: Детальный план GPU-векторизации с разделением на независимые вклады

**Дата обсуждения:** 2025-04-15  
**Статус:** Обсуждено детально, параметры определены. Не реализовано.

### Ответы на открытые вопросы

| Вопрос | Решение |
|--------|---------|
| **float32 vs float64** | Переключаемый параметр `dtype`. Начинаем с float32, бенчмарким точность. |
| **n_max разный в батче** | Padding нулями до `n_max_global` в батче. Лишние — маскировка, не страшно. |
| **Сетка M×b** | 50×50 или 64×64. Потом измельчение между точками где меняется `b_min` или `M_min`. |
| **Библиотека** | **PyTorch** (знакомый API, хорошая GPU поддержка) |
| **GPU память** | **15 GB** |

### Параметры реализации

```python
# Конфигурация
N_mu = 50      # или 64
N_L = 50       # или 64  
N_M = 50       # или 64
N_b = 50       # или 64

dtype = torch.float32  # или torch.float64
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')

# Сетки
mu = torch.linspace(0.1, 7.0, N_mu, dtype=dtype, device=device)
L = torch.linspace(0.1, 4.0, N_L, dtype=dtype, device=device)
M = torch.linspace(0, 10, N_M, dtype=dtype, device=device)
b = torch.linspace(0, 10, N_b, dtype=dtype, device=device)
```

### Ограничение памяти (15 GB)

Максимальный размер батча для Omega_muL:
- Тензор: `(batch, n_max_global, N_p)`
- При n_max=20, N_p=100, float32: `batch × 20 × 100 × 4 байт`
- 15 GB / (20 × 100 × 4) ≈ **1,875,000 точек**
- Но нужен запас на промежуточные тензоры → безопасно **500K–1M точек/батч**

Для сетки 50×50×50×50 = 6.25M точек:
- Батчей: ~10 (по 625K точек)
- Время: ~10 × 3 сек = **~30 секунд** на Omega_muL

### Концепция

Разделить `Omega_ren` на 4 независимых вклада, посчитать каждый на **своей сетке**, сохранить отдельно, потом сложить через broadcast, найти минимум на сетке и уточнить сплайном.

### Структура Omega_ren

```
Omega_ren(M, b, mu, L) = 
    tree(M) 
    + dU_phys(b, M) 
    + Omega_L_phys(L, b, M) 
    + Omega_mu_L_phys(mu, L, b, M)
```

| Вклад | Зависит от | Сетка |
|-------|-----------|-------|
| `tree` | `M` | `M[50]` |
| `dU` | `b, M` | `b[50] × M[50]` |
| `Omega_L` | `L, b, M` | `L[50] × b[50] × M[50]` |
| `Omega_muL` | `mu, L, b, M` | `mu[50] × L[50] × b[50] × M[50]` |

### Шаг 1: Считаем каждую функцию отдельно (батчами на GPU)

**dU_phys(b, M):**
```
Тензор: (50, 50, 100, 100) для (b, M, p, phi)
Сумма по (p, phi) → dU[50, 50]
Время на GPU: < 1 сек
```

**Omega_L(L, b, M):**
```
Тензор: (50, 50, 50, 100, 100) для (L, b, M, p1, p2)
Сумма по (p1, p2) → Omega_L[50, 50, 50]
Время на GPU: ~1-2 сек
```

**Omega_mu_L(mu, L, b, M):**
```
Батчи по ~500K–1M точек (mu, L, b, M)
Для каждого батча:
    n_max_global = max(n_max в батче)  # обычно 10-20
    Тензор: (batch, n_max, 100) для (point, n, p)
    Маска + сумма → Omega_muL[batch]
Собираем → Omega_muL[50, 50, 50, 50]
Время на GPU: ~10-30 сек
```

### Шаг 2: Сохраняем промежуточные результаты

```python
np.save('cache/dU.npy', dU)           # [50, 50]
np.save('cache/Omega_L.npy', Omega_L) # [50, 50, 50]
np.save('cache/Omega_muL.npy', Omega_muL) # [50, 50, 50, 50]
```

**Плюс:** если поменять `g` (tree меняется), остальные вклады не пересчитываются — просто перезагружаем из кэша.

### Шаг 3: Складываем (broadcast)

```python
Omega_ren[mu, L, b, M] = 
    tree[M] 
    + dU[b, M] 
    + Omega_L[L, b, M] 
    + Omega_muL[mu, L, b, M]
```

Размер: `[50, 50, 50, 50]` = 6.25M элементов = **50 MB** (float64) / **25 MB** (float32)

Время: мгновенно (векторное сложение)

### Шаг 4: Грубый минимум (argmin на сетке)

Для каждой пары `(mu, L)`:
```python
grid_2D = Omega_ren[mu, L, :, :]  # [50, 50] для (b, M)
idx = np.argmin(grid_2D)
M_coarse[mu, L] = M_grid[idx // 50]
b_coarse[mu, L] = b_grid[idx % 50]
```

Время: < 1 сек

### Шаг 5: Уточнение сплайном

В окрестности грубого минимума (например, 5×5 точек сетки):
```python
# Берём окно 5×5 вокруг минимума
window_M = M_grid[i-2:i+3]
window_b = b_grid[j-2:j+3]
window_vals = Omega_ren[mu, L, j-2:j+3, i-2:i+3]

# Bicubic сплайн
spline = RectBivariateSpline(window_b, window_M, window_vals)

# Ищем минимум сплайна (L-BFGS-B из центра окна)
result = minimize(lambda x: spline.ev(x[0], x[1]), 
                  [b_coarse, M_coarse], 
                  bounds=[(window_b[0], window_b[-1]), 
                          (window_M[0], window_M[-1])])
```

**Точность:** ~0.001–0.01 (гораздо лучше шага сетки 0.2)

### Оценка времени (всё на GPU)

| Шаг | Время GPU |
|-----|----------|
| dU | < 1 сек |
| Omega_L | 1–2 сек |
| Omega_muL (батчи) | 10–30 сек |
| Сумма + argmin | < 1 сек |
| Сплайн (2500 точек) | 5–10 сек |
| **Итого** | **~20–45 сек** |

## Идея: Адаптивная сетка с интерполяцией

**Дата обсуждения:** 2025-04-15  
**Статус:** Реализовано в `notebooks/39_smart_adaptive.py`

### Реализация

1. Грубая сетка 8×8: grid 5×5 + L-BFGS-B
2. Интерполяция `M_min(μ, L)`, `b_min(μ, L)` на 128×128 (cubic spline)
3. Градиент интерполяции: уточняем только точки с большим `|∇M|` или `|∇b|` (~15–20%)
4. Остальные оставляем интерполированными

### Результаты

- Время: ~1–5 минут на 128×128
- Точность: приемлемая для визуализации
- Проблема: интерполяция может сглаживать острые границы

## Идея: Асимптотические "быстрые пути"

**Дата обсуждения:** 2025-04-15  
**Статус:** Частично используется в `docs/asymptotics.html`

### Суть

При больших `μ` и `L` можно использовать аналитические формулы вместо численных интегралов:
- `μ > 4`, `L > 2`: `Omega_mu_L ≈ -μ³/(6π) + M²μ/(2π)` → сразу знаем M=0 или M>0
- `μ < 2`, `L < 1`: нужны все вклады

### Применение

Для классификации фазы можно пропускать численное интегрирование в асимптотических областях.

## Идея: GPU-векторизация и батчевые вычисления

**Дата обсуждения:** 2025-04-15  
**Статус:** Обсуждено, не реализовано. Требует серьёзной переписи кода.

### Проблема

Текущий подход (последовательный DE + L-BFGS-B для каждой точки `(μ, L)`):
- Слишком медленно для высокого разрешения (128×128 = 16 384 точки)
- Каждая точка требует ~50–100 вызовов `Omega_ren` → часы вычислений
- Нет возможности быстро исследовать параметрическое пространство

### Предлагаемое решение

Полная векторизация: считать `Omega_ren` **одновременно для батча точек** `(μ, L, M, b)` на GPU.

#### Архитектура

```
Сетки: μ[50] × L[50] × M[50] × b[50] = 6 250 000 точек

Разбиваем на батчи по ~10 000 точек (по памяти GPU)

Для каждого батча параллельно:
  1. dU_phys(M, b)          → сумма по (p, phi)
  2. Omega_L(L, b, M)       → сумма по (p1, p2)
  3. Omega_mu_L(μ, L, b, M) → сумма по (n, p) с маской
  4. tree = M²/(2g)
  5. Omega_ren = tree + dU + Omega_L + Omega_mu_L

Для каждой (μ, L) ищем минимум по (M, b) внутри батча
Уточняем минимум сплайном в окрестности
```

#### Что можно векторизовать

| Функция | Сложность | Оценка ускорения |
|---------|-----------|-----------------|
| `dU_phys(M, b)` | 🟢 Легко. 2D интеграл → сумма по сетке | 50–100× |
| `Omega_L(L, b, M)` | 🟢 Легко. 2D интеграл по p1, p3 | 50–100× |
| `Omega_mu_L(μ, L, b, M)` | 🔴 Сложно. Циклы по n, условные ветвления | 10–30× |

**Главная проблема — `Omega_mu_L`:**

Текущий код использует numba-JIT циклы:
```python
for n in range(Nmax + 1):      # Nmax разный для каждой точки!
    if two_roots:              # условие зависит от M, b
        ...
    integral = ...             # интеграл по p
```

Для GPU нужно заменить на **маскирование + padding**:
- Найти `n_max_global = max(n_max)` для всего батча
- Создать тензор `(batch, n_max_global, N_p)`
- Маской занулить недопустимые `(n, p)` для каждой точки
- Суммировать по `n` и `p` векторизованно

#### Оценка памяти (батч = 10 000 точек)

| Тензор | Размер | Память (float64) |
|--------|--------|-----------------|
| `Omega_mu_L` | (10000, 20, 100) | ~160 MB |
| `Omega_L` | (10000, 100, 100) | ~800 MB |
| `dU` | (10000, 100, 100) | ~800 MB |
| **Итого** | | **~1.8 GB** |

Влезает в GPU с 8+ GB памяти.

#### Оценка скорости

**Вся сетка 50×50×50×50 = 6 250 000 точек:**
- Батчей: 625 (по 10 000 точек)
- Время одного батча на GPU: ~1–3 сек
- **Итого: ~10–30 минут**

Сравнение с текущим подходом:
- Последовательный DE: ~6×10⁸ вызовов × 0.01 сек = **~72 дней**
- Параллельно на 4 CPU: **~18 дней**
- GPU батчи: **~10–30 минут**

**Ускорение: ~1000×**

### Открытые вопросы

1. **Библиотека:** JAX, PyTorch или CuPy?
   - JAX: авто-дифф, JIT, `vmap`, но нужно переписывать с нуля
   - PyTorch: знакомый API, но циклы по n сложно векторизовать
   - CuPy: почти numpy, но нет JIT

2. **Omega_mu_L:** Как эффективно векторизовать циклы по `n` с разным `n_max`?
   - Padding + masking
   - Или разбивать на под-батчи с одинаковым `n_max`

3. **Разрешение:** Нужна ли полная сетка M×b = 50×50?
   - Можно сначала найти минимум при b=0 (1D), потом проверить b>0
   - Это сократит M×b с 2500 до ~100–200 точек

4. **GPU память:** Какой GPU доступен? (8 GB? 16 GB? 24 GB?)
   - От этого зависит оптимальный размер батча

## Идея: Адаптивная сетка с интерполяцией

**Дата обсуждения:** 2025-04-15  
**Статус:** Реализовано в `notebooks/39_smart_adaptive.py`

### Реализация

1. Грубая сетка 8×8: grid 5×5 + L-BFGS-B
2. Интерполяция `M_min(μ, L)`, `b_min(μ, L)` на 128×128 (cubic spline)
3. Градиент интерполяции: уточняем только точки с большим `|∇M|` или `|∇b|` (~15–20%)
4. Остальные оставляем интерполированными

### Результаты

- Время: ~1–5 минут на 128×128
- Точность: приемлемая для визуализации
- Проблема: интерполяция может сглаживать острые границы

## Идея: Асимптотические "быстрые пути"

**Дата обсуждения:** 2025-04-15  
**Статус:** Частично используется в `docs/asymptotics.html`

### Суть

При больших `μ` и `L` можно использовать аналитические формулы вместо численных интегралов:
- `μ > 4`, `L > 2`: `Omega_mu_L ≈ -μ³/(6π) + M²μ/(2π)` → сразу знаем M=0 или M>0
- `μ < 2`, `L < 1`: нужны все вклады

### Применение

Для классификации фазы можно пропускать численное интегрирование в асимптотических областях.
